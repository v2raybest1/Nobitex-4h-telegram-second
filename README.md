# Nobitex Trading Signal System

سیستم چندمرحله‌ای تحلیل و هشدار معاملاتی بر پایه داده‌های نوبیتکس و ارسال
پیام از طریق تلگرام.

این پروژه شامل دو بخش اصلی است:

1.  اسکنر عمومی 4H (سیستم قدیمی)
2.  سیستم جدید Daily → Order Block → 4H Entry Confirmation

------------------------------------------------------------------------

# 1) Nobitex 4H Telegram Scanner (سیستم قدیمی)

## هدف

این بخش برای اسکن عمومی بازار در تایم‌فریم ۴ ساعته ساخته شده است.

هدف: - پیدا کردن روند صعودی - پیدا کردن روند نزولی - تشخیص بازار رنج

## فایل‌ها

    nobitex_4h_telegram.py
    .github/workflows/nobitex-4h.yml

## اجرا

زمان‌بندی توسط cron-job.org:

    هر ۴ ساعت

## منطق تحلیل

داده‌های کندل 4H دریافت می‌شوند و اندیکاتورهای زیر بررسی می‌شوند:

-   EMA50
-   EMA100
-   RSI14
-   Stoch RSI
-   ATR
-   CHOP

### سیگنال صعودی

شرایط کلی: - قدرت روند مثبت - EMA50 بالاتر از EMA100 - مومنتوم مناسب

خروجی:

    🟢 صعودی

### سیگنال نزولی

شرایط کلی: - فشار فروش - EMA50 پایین‌تر از EMA100 - مومنتوم منفی

خروجی:

    🔴 نزولی

### رنج

وقتی روند واضح نیست:

    ⚪ رنج

------------------------------------------------------------------------

# 2) سیستم جدید Entry Watch

منطق اصلی:

    Daily Signal
          ↓
    بررسی Order Block توسط کاربر
          ↓
    Watchlist
          ↓
    4H EMA20 Confirmation
          ↓
    Entry Alert

------------------------------------------------------------------------

# مرحله اول: Daily Signal

## فایل‌ها

    nobitex_daily_telegram.py
    .github/workflows/nobitex-daily.yml

## اجرا

بعد از بسته شدن کندل روزانه:

    00:03 تهران

## منطق

بررسی:

-   EMA
-   RSI14
-   Stoch RSI

تنظیم Stoch RSI:

    20,20,5,5

خروجی مشخص می‌کند کدام نمادها:

-   صعودی
-   نزولی
-   رنج

هستند.

------------------------------------------------------------------------

# مرحله دوم: بررسی Order Block

Daily فقط فرصت‌ها را پیدا می‌کند.

کاربر بررسی می‌کند:

-   آیا قیمت به Order Block رسیده؟
-   آیا احتمال برگشت وجود دارد؟

در صورت تایید، نماد وارد Watchlist می‌شود.

------------------------------------------------------------------------

# مرحله سوم: مدیریت Watchlist

## فایل

    nobitex_entry_manager.py

Workflow:

    entry-manager.yml

## دستورات تلگرام

افزودن لانگ:

    /addlong ETHUSDT

افزودن شورت:

    /addshort ETHUSDT

حذف:

    /remove ETHUSDT

نمایش:

    /watchlist

## فایل ذخیره

    entry_watchlist_state.json

------------------------------------------------------------------------

# مرحله چهارم: تایید ورود 4H

## فایل‌ها

    nobitex_entry_scanner.py
    .github/workflows/entry-scanner.yml

## اجرا

هر ۴ ساعت:

    00:05
    04:05
    08:05
    12:05
    16:05
    20:05

## منطق

آخرین کندل بسته‌شده 4H بررسی می‌شود.

مثال:

    12-16 تهران

## شرط LONG

اگر:

    Close > EMA20

باشد، ورود تایید می‌شود.

## شرط SHORT

اگر:

    Close < EMA20

باشد، ورود تایید می‌شود.

------------------------------------------------------------------------

# جلوگیری از پیام‌های تکراری

فایل:

    entry_last_report.json

آخرین وضعیت گزارش‌شده را ذخیره می‌کند.

اگر وضعیت تغییر نکند، پیام جدید ارسال نمی‌شود.

مثال:

    ETHUSDT ⏳

دوباره همان باشد:

هیچ پیامی ارسال نمی‌شود.

اما:

    ⏳ → ✅

باعث ارسال هشدار می‌شود.
